# RIDGELINE — 山地探索关卡生成台

程序化生成可通行的山地图：山脊、盆地、水系、作者通路与降雨径流在同一条流水线里求解，并由一套验收门槛（坡度、净宽、必达区抵达、降雨汇水）决定是否放行。

本轮新增**多尺度局部再塑形**：设计者改动山脊、盆地、走廊或通路后，只重算必要的局部窗口与相关通行走廊；窗口外的已确认地形和种子细节逐顶点冻结不变。细网格、粗层 LOD、碰撞网格与导航图同步采用同一份新地形；接缝、粗细不一致或必达区不可连通都会在界面里给出冲突与可调整范围，必要时整次改动整体撤回。

## 图形入口（主要方式）

山地生成与局部重塑都以**关卡编辑视窗**为主入口：

```bash
npm install
npm run dev
# 浏览器打开 http://localhost:5173
```

界面分三栏：

- **左栏 · 生成内核**：场景、种子、地貌目标、网格分辨率、侵蚀强度、河床/山口锁定、修补偏好，以及「生成关卡」「保存为可通关地图」「载入无断口底图」。
- **左栏 · 局部再塑形**：山脊横移、通行走廊宽度、局部窗口倍率、通路绕行四个滑杆，配合「局部重塑」「采纳为可通关地图」「复位改动」「与完整生成对比」。
- **中栏 · 3D 视窗**：地形网格、水系、作者通路（含净宽红绿着色）、必达区路线与标记；局部重塑后叠加**橙=补丁区块 / 蓝灰=冻结区块**的分块色块和亮色窗口边框。
- **右栏 · 验收结果 / 局部重塑影响**：坡度直方图、通行与降雨验收、修补候选、日志，以及本次重塑的影响报告（受影响地貌层、路线坡度/长度变化、接缝、粗细一致度、冲突与可调整范围、完整生成对照）。

### 推荐操作流程

1. 选一个无断口场景（如「缓坡台地」）或直接点「生成关卡」，等待验收通过。
2. 点「保存为可通关地图」。这一步同时保存了重放配方（recipe）、基准高程 datum 与水系状态——局部重塑需要它们才能在不重新随机化的前提下重放。
3. 拖动「山脊横移」「通行走廊宽度」「局部窗口倍率」「通路绕行」中的任意项，点「局部重塑」。只有覆盖改动与相关走廊的窗口被重算，其余地形冻结在已确认状态。
4. 在右栏「局部重塑影响」查看：哪些地貌层与路线变了、补丁/冻结了多少分块、边界接缝是否超限、粗细网格一致度、以及必达区若不可达时给出的可调整范围。
5. 满意后点「采纳为可通关地图」把它作为下一次局部重塑的基准；不满意点「复位改动」。
6. 想量化局部更新与完整一次性生成的差距，点「与完整生成对比」：界面会列出两套结果的坡度、净宽，以及全场地形的最大/平均高差。

> 界面里的「生成中…」遮罩、状态胶囊和日志由真实运算驱动；局部重塑失败时会在「局部重塑影响」和日志中给出原因与可调整范围，不会用涂抹位移掩盖问题。

## 命令行（辅助）

命令行仅用于无头回归与对照，不替代图形入口。它生成一张干净地图，施加一次作者改动，只重放受影响窗口，并打印接缝 / LOD / 路线报告与完整生成对照：

```bash
npx vite-node --script scripts/reshape.ts --ridge-offset 18 --full
npx vite-node --script scripts/reshape.ts --corridor-width 3 --resolution 96
npx vite-node --script scripts/reshape.ts --route-offset 12 --edit-scale 1.4 --full
npx vite-node --script scripts/reshape.ts --json --ridge-offset -20 > report.json
```

参数：`--ridge-offset <m>`、`--corridor-width <m>`、`--route-offset <m>`、`--edit-scale <×>`、`--resolution <n>`、`--scenario <id>`、`--seed <n>`、`--full`（附带完整生成对照）、`--json`。

## 实现要点

- **冻结与重放**：局部重塑以「上一张可通关地图」为基准，用其重放配方在同一流水线上只重写改动窗口；`mergeExterior` 在窗口外把已确认的高度与水位原样写回，窗口内按同一 `datum`（基准高程与垭口 sill）重算，因此远处地形与种子细节逐顶点不变。
- **真实的判据而非涂改**：局部窗口与越界守卫贯穿地形基底、排水谷切割、侵蚀、走廊整平、填洼与水文；排水与填洼是全局耦合的流域问题，因此这两步始终整场求解，只在写回阶段冻结窗口外，避免把冻结边界当成挡墙抬高内部洼地。
- **同批生效**：局部重建会一次性更新细网格、粗层 LOD（粗网格对同一 spec 独立重放后重采样比对）、碰撞网格（沿用细网格）与导航图；任意一环不通过即整次撤回。
- **边界与保留区**：接缝审计在每个跨窗口边上比较改动前后的落差增量。全局耦合的步骤（填洼、水文）会在窗口换算出的边距上留下一点残差；`mergeExterior` 之后由 `stitchBoundaryBand` 在窗口边距内重算一条渐变边界带（改动足迹之外），让内部新解无缝接回冻结外侧，同时不碰作者改动本身。已确认的必达区着陆台只在改动足迹真正触及其台体时才重新整平，否则在流水线末尾用 `restorePreservedPads` 把确认过的台体原样写回，避免「改动被锁定的景观来解冲突」。
- **冲突与可调整范围**：必达区不可达、无可行坡道、接缝超限、粗细不一致、锁定山口被移动，都会生成结构化冲突，附带 `editScale / corridorWidth / ridgeOffset / passRadius` 等可调范围与建议值。

## 验证

```bash
npm test          # 生成、修补、局部重塑的可通行性与接缝/坡度验收
npm run build     # tsc --noEmit + vite build
```

`tests/reshape.test.ts` 覆盖：山脊横移（冻结窗口外逐顶点不变、接缝、坡度、与完整生成对照）、走廊变窄（仅步道足迹改变，远处地形不动）、跨分块窗口的多块补丁、保留区冻结、无重放配方时拒绝重塑而非重新随机化，以及冲突回退的结构化可调整范围。
